# Live fork and lifecycle known-failure audit

Status: release-blocking audit, 2026-08-31. This is not a claim that Tarit is
bug-free. It maps failures reported or explicitly documented by upstream VMM,
kernel, filesystem, and image ecosystems to Tarit invariants and executable
gates. A row is closed only by code plus a passing real-KVM or destructive
storage/failure test at the layer where the failure occurs.

## Upstream-derived invariants

Each row separates the required invariant from the evidence collected so far.
Evidence marked as passing is limited to the stated host, kernel, image, and
failure matrix; the open cases in the same row remain release blockers.

| Area | Known failure class | Required Tarit behavior | Current evidence / disposition |
|---|---|---|---|
| Running fork | Dirtying can outpace copying; a final device/RAM cut can be inconsistent; a failed handoff can leave two writers or no owner. QEMU treats post-copy as a state machine and documents that loss of either side can lose or indefinitely block the guest. | Bound pre-copy rounds and downtime; atomically capture vCPU/device state with the residual dirty set; keep the source authoritative until child publication commits; on every error resume the source and destroy all staged child state. Test high dirty rate, cancellation at every phase, source/destination death, duplicate requests, and lost acknowledgements. | Bounded live-snapshot convergence writes directly to a private file stage. The final residual and device state share one paused cut; consumed dirty bits are replayed on every error, the source resumes, and staged state is removed. Termination is explicit (`converged`, `diverging`, `timeout`, `max_rounds`) in the public VMM response, and a projected round that cannot fit the remaining pre-copy budget is carried into the final residual. Adjacent dirty PFNs are sorted and copied as runs. Authenticated RAM hashes are computed in the publication scan and transferred through identity-checked scratch ownership; taritd performs no second RAM hash pass. A 1 GiB Ubuntu/Alpine × Linux 6.6/5.10 high-dirty matrix passed, followed by a 1,536 MiB Ubuntu/6.6 pass with 648.5 ms blackout and lazy restored-data verification. A production-disabled failpoint build interrupted ten VMM phases from dirty-log activation through integrity publication; Ubuntu/6.6 and Alpine/5.10 proved immediate source recovery and zero artifact leaks at every phase. Fork requests now persist a tenant/source/target-bound `preparing` record before child creation and commit it with the exact child `created_at` fence before acknowledgement. A true taritd `SIGKILL` after child persistence and before commit/ACK passed Ubuntu and Alpine on Linux 6.6 and 5.10: restart re-adopted the child, a retry returned that child after source deletion, and wrong-source reuse failed closed. Cross-node process-death phase injection and 100-sample distributions remain release blockers. |
| Lazy RAM / UFFD | Fault and eager threads can race and overwrite a page; `UFFDIO_COPY` can lose a race; a pending `UFFD_EVENT_REMOVE` makes UFFD ioctls return `EAGAIN`; mixed-residency chunk prefetch can return `EEXIST` while the actual faulting page remains missing; Linux 6.6 added UFFD ioctl capabilities that broke older fixed handshakes; manager-socket shutdown can race memory-map registration; unmap, remap, handler death, truncated backing, and malformed offsets change the manager's obligations. | Negotiate the runtime UFFD API rather than assuming a fixed feature mask; complete and acknowledge registration before accepting faults; drain REMOVE events before retrying deferred faults; treat `EEXIST` as success only for the faulting page, falling back from authenticated chunk prefetch to a verified page copy; distinguish explicit balloon discard (zero on refault) from suspend eviction (rehydrate from the suspend image); pin backing and authenticated metadata; fail closed rather than abandoning an unresolved fault. | Tarit negotiates REMOVE, UNMAP, and REMAP support before registering guest memory. It uses an in-process handler rather than an external manager socket: registration and handler creation complete before the lazy restore is published, thread-creation failure returns a startup error, and the owned descriptor cannot be transferred to another manager. Unexpected handler exit, panic, descriptor loss, UNMAP, REMAP, malformed event state, and unrecoverable copy failure terminate the one-VM VMM. Real c8i UFFD tests cover handler exit, descriptor loss, UNMAP, REMAP, resident-page discard, REMOVE draining, zero-refault, and mixed-residency chunk fallback. Full API recovery gates forced handler failure across Ubuntu 24.04 and Alpine 3.20 on Linux 6.6.155 and 5.10.230; representative UNMAP and REMAP gates covered Ubuntu/6.6 and Alpine/5.10. Each returned a sanitized failure, left no VMM PID, preserved retryable hibernated state and guest data, and released capacity. This row is closed for Tarit's in-process UFFD architecture. |
| Balloon + restore | A restored balloon queue can contain stale descriptors; balloon inflation can race lazy faults or snapshot reads. Firecracker issue 5566 reports RCU stalls/panics after snapshot resume with balloon activity. Balloon config and used-ring causes can overlap, and an edge-triggered GSI can lose the first batch completion. Balloon `actual` is guest-reported and cannot be a host memory boundary. | Bound every guest PFN request before allocation/read; use the virtio active-high level interrupt contract with EOI resampling; fence snapshot host reads against discard; preserve queue/config state consistently; drain UFFD REMOVE before copying; repeatedly inflate/deflate before and after restore while scanning for stalls, panics, and descriptor loss; enforce host memory with cgroups regardless of balloon telemetry. | PFN input is capped at the Linux/Firecracker 256-PFN request size and read incrementally. The balloon GSI is level-triggered with KVM resampling and pending-cause reassertion. Ubuntu 24.04 and Alpine 3.20 on Linux 6.6.155 and 5.10.230 each passed 20 live-snapshot/lazy-restore/inflate/deflate cycles under a 768 MiB cgroup v2 limit (80 restores), guest-data verification, host-RSS reclaim, and kernel-liveness scanning, with zero OOM kills. No test process or cgroup remained. The balloon/restore blocker and the measured guest-sized snapshot-buffer blocker are closed for this matrix. |
| Clone uniqueness | A fork duplicates kernel CRNG state, `/proc/sys/kernel/random/boot_id`, userspace PRNGs, cached nonces, TLS/session keys, and one-time tokens. Firecracker explicitly considers multi-resume insecure without a generation mechanism; virtio-rng availability or a clock jump alone does not prove immediate reseeding. | Change VMGenID before vCPUs resume, use a guest kernel that handles it, and expose a post-fork generation hook/readiness barrier for userspace state that VMGenID cannot fix. Compare many sibling clones for kernel RNG output, boot/generation identity, cached-token invalidation, and hook completion before ingress/exec/PTY/SSH admission. | Tarit uses the corrected ACPI identifiers (`VMGENCTR`, `VM_GEN_COUNTER`), changes VMGenID before restored vCPUs run, and requires a nonce-bound userspace repair barrier before workload admission. The barrier supplies fresh host entropy with `RNDADDENTROPY`, forces `RNDRESEEDCRNG`, replaces boot/clone identity, and runs the optional root-owned post-fork hook. Linux 6.6 observed the VMGenID notification; Linux 5.10 intentionally used the compatibility barrier without a VMGenID driver. Ubuntu and Alpine c8i fork tests on both kernels produced distinct generation IDs, boot IDs, clone IDs, and first random samples and failed closed on hook failure. Application-specific cached state still requires the hook; VMGenID alone is not represented as sufficient. |
| Time and timers | Snapshot restore can duplicate or jump wall time, TSC deadlines, leases, retry deadlines, and application timers. Firecracker has fixed both restored kvm-clock jumps and restored watchdog soft-lockups. | Test monotonic and wall clocks across long hibernation and sibling fork; restore irqchip/PIT/LAPIC/TSC state compatibly; clear inherited realtime advancement; issue KVM clock control before state capture and after restore where supported; use host monotonic deadlines; never inherit ownership leases from guest time. | Tarit now clears `KVM_CLOCK_REALTIME`, best-effort calls `KVM_KVMCLOCK_CTRL` before paused-state capture and after restore, and passes the focused restore-policy test plus lifecycle matrix. The c8i guest/host combination returns `EINVAL` for the post-restore notification, which is logged rather than hidden. Long-hibernation wall-clock/timer/watchdog/lease tests remain open, so this row is not closed. |
| vCPU MSR state | KVM exposes a host/version-dependent guest MSR list. KVM paravirtual MSRs (`0x4b564d00..0x4b564dff`) carry pvclock, async-page-fault, steal-time, PV-EOI, polling, and migration state; omitting a guest-enabled MSR can resume with stale host state or a broken guest pointer even when general registers look correct. | Derive the migratable save set from `KVM_GET_MSR_INDEX_LIST`, bind it to the CPU/snapshot compatibility manifest, capture every enabled migration-relevant MSR, restore in dependency order, and fail before resume on partial GET/SET. Test pvclock, PV-EOI, steal-time and async-PF enabled/disabled states across builds and kernels. | Tarit now retains its strict architectural set and dynamically adds every host-enumerated MSR in KVM's complete custom range, serializes the exact indices, rejects unsupported destination custom MSRs before SET, chunks future lists at KVM's ioctl limit, and restores async-PF INT before EN plus TSC before TSC-deadline. The c8i jailed gate found and fixed an initialization/seccomp boundary (`fcntl` from lazy `/dev/kvm` cloning), and found that `KVM_GET_MSR_INDEX_LIST` is not exhaustive for readable architectural state (it omitted EFER), so enumeration is intentionally authoritative only for the custom range while strict GET/SET counts guard the fixed set. Boot-enabled workspace tests, clippy, and a 302-operation real-KVM lifecycle run pass. The cross-kernel/build pvclock, PV-EOI, steal-time and async-PF enabled/disabled compatibility matrix remains open. |
| Restored device I/O | UART can wait forever for a lost TX interrupt; vsock can suppress RX, race delivery before transport-reset acknowledgement, or strand an in-flight TX descriptor. Boot-time UART mode changes can truncate the first long command. A drained capture buffer can allocate later on a seccomp-confined vCPU. Slow block I/O can starve unrelated devices if queue work is unbounded. | Snapshot each device during active TX/RX and descriptor publication; persist the full transport gate/cursors; replay necessary queue kicks; complete transport reset before payload delivery; restore serial TX/RX interrupt state; use a short nonce-bound readiness probe and bounded initial wait for framed vsock; keep vCPU-side serial capture allocation-free; bound per-device queue work. | Tarit restores UART programming, bounds descriptor chains, resets captured vsock streams, uses a nonce-bound serial probe, and waits once for the framed vsock channel before serial fallback. Serial capture is permanently bounded/preallocated and control-side drains install its replacement before returning bytes. This fixed Linux 5.10 first-command loss and an intermittent seccomp `openat` vCPU death found by the mixed-OCI soak. A separate c8i gate passed 40 fresh create/readiness/exec/security/stop cycles across Ubuntu/Alpine and Linux 6.6/5.10 with no abnormal vCPU exit. Explicit UART-in-flight, vsock-in-flight-TX, reset-ack ordering, bare pause/resume, and slow-block fairness tests remain release blockers. |
| Snapshot format and compatibility | State formats are version-, CPU-, kernel-, device-, and topology-sensitive. Historical Firecracker regressions corrupted differential memory above 3 GiB or with multiple slots, corrupted a loaded source when it was reused as snapshot output, and produced misleading first diffs when dirty tracking was not active. `mincore`-derived diffs are unsafe if swap can hide dirtiness. Partial or incompatible state can boot incorrectly instead of failing immediately. | Authenticate manifest and chunks; bind VMM build, CPU template, kernel, device topology, memory-slot map, sizes, parent lineage, dirty-tracking mode, swap policy, and volume identities; prohibit source/output aliasing by identity, not just path spelling; reject trailing data, downgrade, missing parents, or unsupported device state before allocation/resume. Test more than 3 GiB, multiple memory slots, source/output hardlinks, first-diff semantics, and swap. | Authenticated manifests, opaque artifacts, CPU templates, input bounds, parent restrictions, and hostile-path tests exist. The E820 map matches the real 3.25–4 GiB MMIO aperture. Guest RAM remains packed in one contiguous host/snapshot mapping while KVM registers a low slot and relocates the remainder to a high slot at 4 GiB; KVM dirty PFNs and guest-physical device ranges are translated to packed offsets. A 4 GiB c8i live-snapshot/lazy-restore matrix passed Ubuntu/Alpine × Linux 6.6/5.10 with the 768 MiB high slot visible at `0x100000000-0x12fffffff`, in-memory proof verification, and 15.2–25.3 ms final stops. Source/output alias, first-diff, swap, and cross-build/cross-template negatives remain open. |
| CoW disk and artifacts | Reflinks consume new blocks on later writes and can hit ENOSPC despite a cheap fork. Crash durability requires file and directory sync at publication boundaries. Deleting or mutating a mapped source breaks lazy children. | Reserve projected write/snapshot headroom, stage with create-new/no-follow, reflink then verify, fsync data and containing directories, atomically publish, pin immutable sources while referenced, and make rollback leak-free on ENOSPC/EIO/short copy. | Admission pressure guards and staged ownership exist. A 1.5 GiB c8i run reproduced a second-full-copy publication `ENOSPC`; live VMSN RAM is now block-aligned and range-reflinked from the private stage on CoW filesystems. The same run exposed a 209 s Btrfs CoW residual-update stall; empty Btrfs stages are now NOCOW before allocation, reducing the loop-device path to 6 s, while the qualifying ext4 stage completed the same residual in 648.5 ms. The loop-backed Btrfs device is retained as a correctness/ENOSPC fixture, not a latency reference. Deterministic near-ENOSPC tests for every publication phase plus crash/restart/fsck verification remain open. |
| NFS/shared volumes | Soft mounts can return errors and cause silent corruption; server restart can stall hard mounts or invalidate handles; `sec=sys` does not protect data in transit; detach can race open users. | Default to NFSv4/TCP hard semantics, require an explicit security flavor (production default `krb5p` or an equivalently protected private transport), bound orchestration without converting storage operations to soft I/O, generation-fence attachments, and refuse detach while busy. Test server loss/restart, stale handles, retransmission, fsync, concurrent detach, and node loss. | Provider-neutral NFS executor, identity/generation fencing, reconnect, and busy-detach tests exist. Kerberos/privacy and destructive server-loss/fsync recovery qualification remain open. |
| Lifecycle concurrency | Duplicate create/delete/resume/fork, retries after timeouts, and delete racing snapshot can violate linearizability or resurrect terminal IDs. | Single-flight each identity transition; revalidate durable state after waiting; return one committed terminal result; deleted IDs stay terminal across every route; 429/5xx leaves prior state and capacity accounting intact. | Model-based API/SQLite/process/jail/artifact reconciliation found and fixed concurrent double-delete and the UFFD/balloon failures above. Four deterministic 40-step seed paths (`42`, `1337`, `202609`, `424242`) pass on c8i with three-VM capacity. Ten VMM snapshot/publication phases have deterministic rollback injection. Local and PostgreSQL stores reserve every VM id, including unlimited tenants, and bind explicit fork ids to one tenant, source, source host, and target host. Active duplicate attempts cannot share the reservation; committed retries require the exact child-incarnation fence and return HTTP 200. A four-lane kill-9/restart gate closed the local fork process-death and lost-acknowledgement path and found the digest-suffixed restore-overlay reconciliation defect. A PostgreSQL+mTLS gate on Linux 6.6 and 5.10 now kills the target after durable child creation but before operation commit, then proves exact retry, replay, wrong-source rejection, incarnation fencing, stale-owner recovery, volume recovery, repair, and GC. Physical multi-host failure and additional transfer/publication phase injection remain open. |
| Isolation | Worker KVM must remain available while nested VMX/SVM and `/dev/kvm` are absent in the customer guest. A VMM escape has more impact when paths, namespaces, cgroups, or seccomp are weak. | Mask VMX and SVM in every vCPU CPUID path; never pass `/dev/kvm`; use per-VM UID/GID, mount/PID/network namespaces, cgroups, no-new-privileges, restrictive seccomp, immutable trusted inputs, and separate authenticated peer control. | CPUID masking is implemented in the shared boot/restore path and c8i tests assert worker VMX plus guest VMX/SVM and `/dev/kvm` absence. Continue kernel/microcode patching and syscall/path adversarial gates. |
| OCI input | Tags mutate; descriptor bytes can mismatch their digest; tar layers can traverse, overwrite through links, create devices, or exhaust disk/inodes; config semantics differ across images. | Resolve once to digest, verify descriptor size/digest before heavy work, require signature/provenance in production, unpack in a private no-follow workspace with path/type/size/inode limits, and bind converted rootfs plus injected agent/kernel/config digests into admission. | Digest/signature policy and hostile extraction tests exist; seven-image c8i compatibility passed. Decompression-bomb/inode-exhaustion and registry interruption/resume gates remain open. |

## Release execution rule

Unit tests and mocks can reject malformed state and validate local transition
logic, but they cannot close KVM, UFFD, kernel-timer, filesystem-crash, NFS
recovery, or isolation rows. Those rows require recorded c8i (Ubuntu guest) or
purpose-built destructive storage evidence. Randomized tests must print the
seed, selected object, operation, and pre-state, reset to the same baseline for
each seed, and preserve artifacts/logs on failure. Soak tests must also scan
guest and host logs for stalls, panics, OOMs, seccomp kills, UFFD handler exit,
and leaked processes/mounts/files.
